# Body Repair AI

Короткая инструкция по запуску: [START.md](START.md).

План следующих улучшений и правила накопления данных находятся в [ROADMAP.md](ROADMAP.md).

Локальная лаборатория для ретуши фотографий кузовных деталей по отдельной маске. Проект строится так, чтобы изображения оставались на компьютере, а интерфейсы и модели можно было заменять независимо.

## Текущий статус

Первый каркас содержит:

- доменную модель задания;
- локальное файловое хранилище для будущего датасета;
- подготовку бинарной и мягкой масок;
- заменяемый inference-backend;
- конфигурацию через `.env`;
- тесты базовой логики.

Для быстрой проверки без модели доступен `mock`-backend. Рабочий локальный
baseline использует ComfyUI и SDXL Base; фотографии не отправляются во внешние сервисы.

## Быстрый старт

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
pytest
```

Запуск локального интерфейса:

```powershell
.\scripts\start.ps1
```

Затем открыть `http://127.0.0.1:8000`. Разметка рисуется прямо поверх фотографии.
Каждый тип хранится отдельным слоем, поэтому одна область может одновременно
быть грязной, поцарапанной и иметь вмятину:

- голубая разметка в редакторе сохраняется белым и обозначает кузовную деталь;
- красный обозначает вмятины;
- жёлтый обозначает грязь;
- пурпурный обозначает царапины;
- чёрный фон и ластик обозначают защищённую область.

Белая область детали сохраняется как контекстная `part mask`, но сама по себе
не разрешает модели перерисовывать всю деталь. Дефекты обрабатываются отдельными
этапами в порядке: вмятины → царапины → грязь. В режиме `mock` результат равен
оригиналу — этот режим нужен для проверки сохранения файлов, масок, метаданных
и пользовательского сценария.

### Локальный SAM 2

SAM 2.1 tiny работает отдельным локальным микросервисом на `127.0.0.1:8190`.
Основное приложение остаётся работоспособным без него: деталь всегда можно
выделить вручную.

После установки ComfyUI один раз загрузите модель SAM 2 (около 160 МБ):

```powershell
.\scripts\setup-sam2.ps1
```

Отдельный запуск сервиса:

```powershell
.\scripts\start-sam2.ps1
```

Обычный `start-local.ps1` запускает ComfyUI, SAM 2 и веб-приложение вместе.
В редакторе выберите слой «Деталь», нажмите `SAM 2` и протяните рамку вокруг
одной кузовной детали. После этого SAM 2 доступен и для активных слоёв дефектов:
выберите грязь, царапину или вмятину и обведите нужную область тесной рамкой.
Дефектная маска добавляется к слою и обрезается границей детали. Для простых
объектов достаточно короткого клика. Любую маску можно исправить кистью и ластиком.

### Подключение ComfyUI

Для NVIDIA можно установить изолированную portable-сборку и официальный SDXL
checkpoint одной командой (потребуется около 12–15 ГБ):

```powershell
.\scripts\setup-comfyui.ps1
```

После установки весь стек можно запустить одной командой:

```powershell
.\scripts\start-local.ps1
```

Если на порту `8000` остался старый `mock`-сервер, сначала остановите его
сочетанием `Ctrl+C`.

Скрипт поднимает ComfyUI в фоне, ждёт его готовности и запускает веб-приложение.
Логи ComfyUI сохраняются в `.runtime/logs`. Для раздельной отладки можно в
первом терминале запустить ComfyUI:

```powershell
.\scripts\start-comfyui.ps1
```

После появления адреса `http://127.0.0.1:8188` во втором терминале запустить
приложение:

```powershell
.\scripts\start.ps1
```

Готовый API workflow находится в `workflows/sdxl_inpaint_api.json`. Он меняет
только маскированную область, использует умеренный denoise `0.38` и рассчитан
на первый сравнительный baseline, а не на финальное качество.

Приложение загружает в ComfyUI только crop с контекстом и его маску, ждёт
результат, возвращает crop к исходному размеру и принудительно сохраняет
оригинальные пиксели вне мягкой маски.

Crop всегда масштабируется с сохранением исходных пропорций. Недостающие до
кратного 64 размеры заполняются временными полями, которые удаляются до возврата
результата. Длинные маски автоматически делятся на локальные перекрывающиеся
участки (`MAX_MASK_TILE_SPAN`, по умолчанию 384 пикселя), поэтому фотографии 2K
и выше не сжимаются целиком в один деформированный кадр. За пределами явно
закрашенной области остаются исходные пиксели.

### Экспериментальный перенос по донору

В раскрывающемся блоке «Эксперимент: заменить деталь» можно загрузить хорошую
фотографию той же детали. Деталь на исходном фото размечается обычным слоем
«Деталь», а на доноре — отдельной маской через SAM 2 или готовым PNG. Первый
baseline локально совмещает ограничивающие рамки масок, переносит только
пересечение деталей и при необходимости подгоняет цвет и яркость. Он предназначен
для близких ракурсов; перспективное выравнивание по ключевым точкам будет
следующим этапом. Принятые донорские результаты сохраняют донор и его маску для
будущего обучения.

### Разметка готовых образцов «до / после»

Если хороший результат был получен во внешнем редакторе, его можно добавить в
локальный датасет без повторной генерации. Создайте отдельную папку внутри
`data/references` с любым понятным именем и положите в неё два изображения
одинакового размера:

```text
data/references/моё-имя/
├── before.png
└── approved_after.png
```

В интерфейсе в блоке «Эталонные пары» нажмите «Обновить список», выберите папку
и нажмите «Открыть образец». Слева откроется исходник для обычной послойной
разметки: деталь, вмятины, царапины и грязь. Справа показывается утверждённый
результат. После нажатия «Сохранить разметку в датасет» приложение создаёт один
идентификатор и раскладывает связанную пару по существующей структуре:

- исходник — `data/raw/<id>/original.png`;
- маски — `data/annotations/<id>`;
- хороший итог — `data/accepted/<id>/result.png`;
- описание — `data/jobs/<id>.json`.

В папке образца также сохраняются маски и `metadata.json`. Повторное сохранение
того же образца обновляет его разметку, а не создаёт дубликат. Такие пары уже
пригодны для контроля качества и будущего обучения; само обучение модели будет
отдельным этапом после накопления достаточного количества разнообразных примеров.

## Правила хранения данных

- `data/raw` — неизменяемые оригиналы;
- `data/annotations` — маски;
- `data/candidates` — результаты отдельных запусков;
- `data/accepted` — принятые результаты;
- `data/rejected` — отклонённые результаты;
- `data/exports` — подготовленные версии датасета.

Каталоги `data`, `models` и файлы весов исключены из Git.

## Работа с Git

Основная ветка — `main`. Для экспериментов создавайте отдельные ветки:

```powershell
git switch -c experiment/sdxl-inpaint
```

Workflow ComfyUI и код адаптера коммитятся, веса моделей и фотографии — нет.
